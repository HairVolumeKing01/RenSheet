# RenSheet

二次元拼团金额计算工具集。纯前端，浏览器内完成 Excel 解析、计算、导出。

## 技术栈

| 层 | 技术 |
|---|---|
| 页面 | HTML5 / CSS3 / Vanilla JS |
| Excel 解析 | [SheetJS](https://sheetjs.com/)（本地 `lib/xlsx.full.min.js`） |
| Excel 导出 | [ExcelJS](https://github.com/exceljs/exceljs)（本地 `lib/exceljs.min.js`） |
| 截图识别 | PP-OCRv4 / ONNX Runtime Web（本地 `lib/ocr/`，WASM 单线程） |
| 视觉 | `lib/water.js`（水面/账页背景）+ 纯 CSS 主题 |
| 持久化 | localStorage 保存设置；相册排表用 sessionStorage 保存本次草稿与交接 |
| 部署 | Cloudflare Pages / 任意静态托管 |

无框架、无构建工具、无后端依赖。依赖库全部放在 `lib/` 本地引用，不加载任何 CDN。除相册排表外，其余页面可直接双击 HTML 离线使用；相册排表需通过 HTTP/HTTPS 访问。所有识别与计算在用户浏览器完成，文件不会上传到任何服务器。

## 页面功能

| 页面 | 入口 | 功能 |
|---|---|---|
| 肾表 | shenbiao.html | 导入排表 Excel → 按人聚合 → 分类式/清单式肾表导出。支持多 sheet 单文件或分表上传两种模式，可选定尾模式、额外费用均摊（点数/人数/本体肾额比例）与满赠预分配 |
| 国际表 | guoji.html | 排表 + 重量参数 → 按重量分摊国际运费。支持多 sheet 单文件或分表上传两种模式；可选「全重分摊 / 净重分摊」两种算法，克重支持「统一克重 / 分角色克重」 |
| 二调退补表 | RatioFix.html | 原排表 vs 拆配排表 → 按角色热度自动配平或手动配平 → 每人补款/退款明细。仅支持单 sheet 排表，热度列支持拖拽排序 |
| 使用指南 | guide.html | 纯展示页：数据流动画 + 三工具分步演示动画（与工具当前功能同步，如分角色克重、热度拖拽、Step 3 改名校验） |
| 相册拼谷排表生成 | ocr.html | 群相册评论截图 → 本地 OCR → 角色对照表归一 → 全局校对 → 配数与凹/all 结算 → 标准排表导出或转入肾表 |
| 打赏 | dashang.html | 老板请赏光，黑金 KTV 主题赞赏页 |

## 数据流

```
导入排表(.xlsx) → SheetJS 解析 → 按人聚合 → 生成表格 → 预览 → ExcelJS 导出
```

### 排表格式规范

每个排表文件可包含多个品类（每个 sheet 一个品类），也可分文件上传：

| 位置（Excel 行号） | 内容 | 说明 |
|---|---|---|
| A1 | 品类名 | 如"吧唧"、"立牌"，不可为空 |
| B1 起 | 必须为空 | 格式校验项 |
| 第 2 行 | 角色名列头 | 保持原文，不缩写不删字；同一 sheet 内不可重复（国际表分角色克重以该行原文为键） |
| 第 3 行 | 单价 | 该角色谷子单价（国际表计算不使用此行） |
| 第 4 行起 | 购买数据 | 每格填购买人名字，不买留空 |

## 核心函数

### 解析层
- `getSheetKind(wb)` — 校验排表格式，提取 A1 品类名
- `parseSheet(wb)` — 遍历数据行，生成 `{person, character, label, kind, price}` 购买记录
- `colToLetter(col)` — 列号转字母（0→A），用于错误定位
- `tryParsePreview(wb)` — 导入时即解析，返回 CN/角色/记录统计

### 聚合层
- `processAllFiles()` — 合并所有文件，按人名聚合到 `personMap`
- `getSortedKinds(personMap)` — 品类排序（吧唧>透卡>立牌>其他）

### 输出层
- `buildCategorizedTable(data)` — 分类式表格
- `buildListTable(data)` — 清单式表格
- `renderPreview()` — HTML 预览渲染
- ExcelJS 导出 — 主题色标题行/表头/交替数据行

### 草稿系统
- `saveDraft()` — 序列化状态到 localStorage
- `restoreDraft()` — 页面加载时自动恢复
- `clearDraft()` — 导出成功后清除

## 主题系统

16 套颜色主题：原有 12 套冷色与中性色主题，以及琥珀、陶土、暖玫瑰、暖棕 4 套暖色主题，统一应用于表格标题行、表头、交替数据行和 Excel 导出。

## 肾表定尾模式

- 固定定金直接输入金额，例如 `20`；比例定金必须带 `%`，例如 `30%`。
- 尾款 = 总肾 − 定金。比例模式下，定金 = 总肾 × 比例。
- 开启后输出金额列为“定金 | 尾款 | 总肾”，并校验定金合计 + 尾款合计 = 总肾合计。

## 肾表其他费用（均摊）

- 输出设置勾选「添加其他费用」，填写总金额并点击确认，再选择均摊模式（三选一）：
  - **点数均摊**：单人 = (总费用 ÷ 总点数) × 单人点数
  - **人数均摊**：单人 = 总费用 ÷ 人数
  - **本体肾额比例均摊**：单人 = (个人本体肾 ÷ 总本体肾) × 总费用
- 开启后金额列变为“本体肾 | 其他费用 | 总肾”；同时开启定尾模式时列变为“本体肾 | 其他费用 | 定金 | 尾款 | 总肾”，定尾基数 = 总肾（本体肾 + 其他费用）。
- 单人其他费用统一进一法保留两位小数，合计允许略大于总费用；第六步校验仅针对总肾。

## 国际表克重方式（2026-08-16）

每个排表条目（多 sheet 模式下的一个 sheet / 分表模式下的一个文件）独立选择克重方式：

| 方式 | 本体重量计算 |
|---|---|
| 统一克重（默认） | 点数 × 单点克重(g/点) |
| 分角色克重 | Σ(该 CN 在该角色列的点数 × 该角色克重) |

- 克重键 = 排表第 2 行列头原文；同一 sheet 内列头全局唯一，一列一个克重，不做合并或缩写。
- 选中「分角色克重」立即列出该 sheet 的全部列头与本表点数，必须逐个填完才能解析；有点数而无克重（或克重 ≤0）时点击「解析此排表」报错并高亮缺失行，禁止解析。
- 有列头但整列无人购买（点数 = 0）直接报错，该排表无法参与解析；统一克重与分角色克重两种方式都会拦截，上传预览即提示。
- 校验项「校验总点数」与「校验总本体重量(g)」均可留空；重量校验容差 |差| ≤ 0.01g 判通过。
- 跨 sheet 不继承克重，每个 sheet 独立填写；导出列结构、箱摊与费率逻辑不变，只替换逐 CN 本体重量的来源。
- 解析结果保留 `CN | 点数 | 本体(g)` 小表，另加可展开的「角色 × 点数 × 克重 = 小计」明细表（默认收起）。
- 必填项以砖红 `※` 标注：总国际运费、总包裹重量、种类名称、单点克重、角色克重；可选校验项不加标记。

## 二调退补表当前规则（准则配平流水线，2026-08-15）

- 调价器以拆配表角色为准，原表独有角色按拆配点数 0 处理且不显示。
- 原调价 = 原排表单价 − 原排表均价；二调从原调价开始，不读取拆配表第三行作为调价起点。
- 原排表均价仅由原排表的“单价 × 点数 ÷ 总点数”自动计算，从第六位小数开始四舍五入并固定显示五位且不可编辑；拆配表均价与总点数由用户填写，系统据此独立校验两张表总价是否相等。
- 第一步解析失败时，红色提示可展开查看问题明细。
- 新单价 = 拆配表均价 + 最终调价；原肾 = 原排表按原单价聚合；现肾 = 拆配表按新单价聚合；红补蓝退 = 现肾 − 原肾（正数为补款，负数为退款）。
- 自动配平以热度准则为核心：加价优先给新增排第一角色 → 真热门缺配（越热越缺涨越多）→ 普通热门缺配（按缺配比例）→ 零调价/冷门缺配（少量）；减价为完全反面，冷门爆配越爆越冷降幅越大。点数不变角色保持不动，实在无解才微动（±原价 10%）。
- 真热门判定：原调价 >0 角色的相邻差异超过基准中位数 2 倍且大于 2 元时，断层靠前的角色为真热门。
- 同锚点组：原调价相同且点数变化差 ≤2 的角色组内水位均摊，调价保持接近（差 ≤2 步）。
- 新增角色排热度第一：新单价大幅高于其他热门（锚角色原调价 + max(3元, 锚×30%)），多个新增角色按热度梯度递增；加价需求优先由它们承担。
- 层级体系：L0-L3 标准准则（20%/40%/50% 幅度）→ L4 扩容层（缺配热门新单价上限自动从 3 倍原均价扩容到 10 倍，点数不变只 ±10%，反方向锁死）→ L5 最终层（反方向才放开，顺序仍按准则）。
- 多方案为精度递进三档：整数元 → 0.1 元 → 0.01 元步长，主方案选“最符合准则层级中精度最粗”的档位，“换调价”按层级升序切换，不重算。
- 调平方式仅两档：“准则配平（推荐）”与“轻约束调平（兜底）”。轻约束只保证热度排序与新单价非负。
- `Σ(拆配点数 × 调价)` 以整数分严格等于 0；自动方案可继续手动核验和修改，手动调价严格配平后即可进入下一步。

## 相册拼谷排表生成当前规则（2026-09-28）

**流程**：一次导入多张清晰分图 → 按文件名自然排序并确认图片顺序 → 按顺序全部识别 → 统一校对昵称、正文与角色归属 → 选择模式并确认排表 → 导出或转肾表。建议避免超长截图；识别、计算和图片对照都在本地完成。

**图片与校对**
- 图片按内容指纹防重，改名重传也不重复加入；成功图片不重复识别，失败图片可单独重试。
- 日期只作辅助信息，日期缺失或末尾被裁切不会阻止生成排表。
- 图片卡片可拖拽排序，手机使用排序手柄；调整后重新确认。先选中评论，再在其后新增；图内插入顺序随图片排序和草稿恢复保留，内容同步到实时排表与导出。
- 原图与评论并排对照，支持来源筛选、只看待核对项、补充或显式忽略评论。相邻截图边界内容重叠时，提示确认保留或忽略，避免误删真实重复留言。
- 使用说明、角色对照与单价折叠区采用水色标题栏、清晰边框和展开/收起提示；使用说明第 2 步简述原图校对、评论新增/忽略与角色归属确认。
- 刷新保留队列、评论、角色列顺序及校对状态。小图片缓存原图；未缓存的原图可补选，已识别评论不会再次追加。STEP 1 的“重置”确认后清空本次排表与草稿，保留已保存的角色对照；处理期间不可重置。

**角色归属与模式**
- 称呼可修改归属、手动新增、忽略或恢复。自动建议需由用户确认，确认结果保存在浏览器本地；人工列顺序保持不变。
- 先选择单领模式或配比模式，再填写输出参数。单领按实际数量排列，无需总配数；凹/all 必须补成明确数量。
- 配比模式的总配数是每个角色的相同正整数限额。凹/all/全占该角色剩余配数，之后同角色记录不计入排表，并列出提示。
- 超出限额的底部整行置灰，整行所有角色都不计入有效配数，优先保留最早排位；增大总配数可恢复灰行。

**排表产出**
- 每个规范角色一列，每格表示该 CN 购买 1 个，表格上方的左右箭头调整列顺序。
- 存在灰行时，导出或转肾表前选择删除灰行、保留灰行或取消。删除仅作用于输出文件；保留的 Excel 也标灰，所有数据仍会参与肾表计算。
- 标准结构：A1 品类名，第 2 行角色，第 3 行单价，第 4 行起 CN 数据，A 列序号；B1 及其后为空。STEP 3 及悬浮预览使用同一导出数据与排版，显示单价、列顺序与灰行；列移动按钮和数量统计位于表外，Excel 不增加统计行。
- STEP 3 提供肾表页相同的 16 套配色，标题、表头与数据行样式同步到实时表及 Excel，灰行优先保持灰色。文件名称可单独重命名，默认使用品类名；文件名不改变 A1 品类名，设置随草稿恢复，重置时清空。
- 内容、模式、配数、价格或列顺序修改后，必须重新确认校对才能导出。日期可留空，未知昵称或数量须补齐或显式忽略。

## 本地开发

除 `ocr.html` 外，其余页面直接用浏览器打开 HTML 文件即可，无需启动服务器（它们只依赖 `<script src>`）。

`ocr.html` 的识别模型是 WASM，浏览器在 `file://` 下会禁止动态 `import()` 与 `fetch()`，双击打开必然报 `no available backend found`，**必须通过 HTTP 访问**：

```bash
node serve.mjs            # 本项目自带的零依赖静态服务器，默认 8000 端口
# 然后打开 http://localhost:8000/ocr.html
```

其他等价方式：

```bash
npx serve .
python -m http.server 8080
```

线上站点是 https，不受该限制。

- **分级调价差异约束**：自动配平以原调价为锚点。小差异二调幅度为原单价的 5%～10%，中差异为 10%～20%，大差异为 20%～40%；幅度约束作用于相对原调价的二次调整量。
- **分层放宽顺序**：第一层只修改点数差异角色；无精确解时加入中间热度角色，再加入其他角色。前三层保持 40% 总上限；最终放宽层仅对点数变化角色提高到 50%，点数未变化角色始终锁定原调价。
- **热度顺序硬约束**：所有自动候选的最终调价必须按用户确认的热度从高到低非递增排列。不得为配平破坏热度顺序；无合法候选时直接提示无解。
- **热度断层兜底**：常规约束完全无解时，按相邻确认热度差从大到小逐步开放断层角色，优先在新单价 `0～拆配均价×3` 内精确配平；仍无解时最后放宽到 4 倍。热度顺序始终不可突破，页面仅标注“热度断层兜底”或“4倍极限兜底”。
- **最冷角色增点规则**：确认热度最冷的角色若比原排增加超过 3 点，其最终调价必须低于原调价；断层兜底必须将该角色纳入求解，不允许所有候选都保持不变。
- **热度两端保护**：热度前 25% 的角色优先限制大幅降价，后 25% 的角色优先限制大幅涨价；只有前序层无解时才逐步放宽。
- **多角色联合求解**：大额配平差值由多个角色共同承担，再进行精确收尾，避免双角色求解无解或将差额集中到单个角色。
- **角色热度确认**：每次导入两张排表进入第二步，都必须先调整并确认完整热度顺序；系统默认按原调价从高到低排列，确认后的从左到右顺序是所有角色自动调价的唯一热度依据。
- **新增角色前列规则**：新增角色排在旧角色之前时，新单价下限为热度后一位的新单价加 2 元，上限为拆配均价 3 倍；连续新增角色逐级保持至少 2 元价差，优先级仅低于零误差和价格安全约束。
- **新增角色换方案规则**：“换调价”的备选方案必须优先提高前列新增角色调价，相对首个方案至少有一个新增角色增加 2 元，且任何前列新增角色都不能降价。
- **未变化角色锁定**：点数未变化角色的最终调价必须等于原调价，不参与任何常规或兜底配平。
- **点数方向约束**：旧角色点数减少时优先保持或提高调价，点数增加时优先保持或降低调价；前三层禁止反方向移动，最终放宽层的反向幅度也不得超过原单价的 5%。
- **有效换调价**：备选方案与其他可切换方案之间，每个发生变化的角色调价差必须在 0.5～10 元，合计差至少 1 元；否则不计为有效方案。
- **拆配角色范围**：调价器以拆配表角色为准；原表存在但拆配表没有的角色按 0 点处理，不写入第二步调价表、确认表和新排表。

## FAQ

**Q: 为什么刷新后文件没了？**
A: 浏览器安全限制，File 对象无法序列化存储。刷新后草稿系统会恢复参数和主题，但需要重新上传文件。

**Q: 大批量文件会卡吗？**
A: 所有处理在浏览器主线程运行，建议单次不超过 50 个排表。国际表上限 50 个，肾表上限 10 个。

**Q: 支持什么 Excel 格式？**
A: 只支持 `.xlsx`。`.xls`、`.csv`、在线表导出须先用 Excel/WPS 另存为 `.xlsx`。

**Q: 数据安全吗？**
A: 纯前端，排表文件不会上传到任何服务器，所有计算在本地完成。
